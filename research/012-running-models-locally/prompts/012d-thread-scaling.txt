The scheduler stores tasks in a dictionary keyed by task identifier. Each task has a status, a priority, a creation timestamp, and a list of dependency identifiers. Valid statuses are pending, running, completed, and failed. A task may run only when every dependency exists and has completed successfully.

The repository currently contains functions for adding tasks, retrieving tasks, marking tasks as completed, and listing pending tasks. The listing function currently returns pending tasks in dictionary insertion order. The requested change is to make task selection deterministic and priority-aware.

Tasks with equal priority should be ordered by creation timestamp from oldest to newest. If priority and creation timestamp are both equal, use the task identifier as the final deterministic tie breaker.

The function must not mutate the task dictionary or any task object. A limit of zero should return an empty list. A negative limit should raise ValueError. Missing dependencies make a task not ready. Dependencies that are pending, running, or failed also make a task not ready.
