# Module 9 Threat Model

## Protected assets

For these experiments, Hewn should protect:

1. files outside the authorized repository workspace;
2. repository files outside the scope granted to a tool operation;
3. host environment values that have not been explicitly granted;
4. host commands and resources outside the coding task's authority;
5. the integrity of the tool-policy boundary itself.

## Untrusted inputs

The following are treated as untrusted:

- language-model output;
- tool arguments generated by the model;
- repository source code;
- comments;
- documentation;
- test files;
- filenames;
- symbolic links;
- generated artifacts;
- command strings;
- command output returned to the model.

Repository content is evidence about the repository. It is not an authority
source.

## Trusted components

For the purpose of Module 9, the deterministic Hewn runtime and its policy
configuration are inside the trusted computing base.

The model is not.

The repository is not.

The operating system is assumed to behave according to its documented file
and process semantics.

## Authority model

An action is permitted only if it is within authority explicitly granted by
the Hewn runtime.

Authority is not inferred from:

- model confidence;
- natural-language claims of necessity;
- instructions contained in repository files;
- instructions contained in command output;
- successful execution of a previous action.
